# Профиль площадки: Дзен

Сведения ниже предоставлены пользователем напрямую (документ загружен 2026-11-17). Профиль задаёт требования к SEO, рекомендательной ленте, заголовкам, обложкам, удержанию, структуре текста и финальной проверке материалов для площадки «Дзен».

## 1. Роль площадки

Дзен — одновременно контентная платформа, рекомендательная система, источник поискового трафика, площадка для экспертного продвижения бренда и площадка для платного продвижения статей через VK Рекламу.

Поэтому статья для Дзена должна одновременно:

- соответствовать поисковому интенту;
- содержать релевантную SEO-семантику;
- привлекать внимание в рекомендательной ленте;
- удерживать пользователя после открытия;
- стимулировать дочитывание;
- демонстрировать экспертность;
- давать пользователю самостоятельную ценность;
- не нарушать требования Дзена.

## 2. Главная модель статьи

Статья для Дзена строится по модели:

> КАРТОЧКА → ОТКРЫТИЕ → ПЕРВЫЕ 10–15 СЕКУНД → УДЕРЖАНИЕ → ДОЧИТЫВАНИЕ → РЕАКЦИЯ → ПЕРЕХОД / ПОДПИСКА / СЛЕДУЮЩИЙ МАТЕРИАЛ

SEO-оптимизация является только одной частью задачи.

## 3. Основная задача Article Writer

Не писать классическую SEO-статью вида «определение → виды → преимущества → инструкция → FAQ» только потому, что такая структура привычна.

Структура должна учитывать:

- запрос;
- поисковый интент;
- интерес пользователя;
- информационный конфликт;
- практическую пользу;
- возможность удерживать внимание до конца.

## 4. Заголовок

Заголовок — один из главных элементов статьи. Он должен:

- ясно сообщать тему;
- вызывать интерес;
- содержать конкретную пользу или проблему;
- соответствовать содержанию;
- не обманывать ожидания;
- естественно содержать основной запрос или важную сущность, если это возможно.

Для статей, которые потенциально будут продвигаться через VK Рекламу, целевой предел — до 70 символов.

## 5. Кликбейт запрещён

Нельзя использовать заголовки, которые обещают то, чего нет в статье. Избегать конструкций:

- «Вы не поверите...»
- «Шок!»
- «Вот что скрывают...»
- «Все делают это неправильно...»
- «Этот способ изменит вашу жизнь...»

Допустимо создавать любопытство, если статья действительно отвечает на поставленный вопрос.

## 6. Варианты заголовков

SEO Analyst должен предложить минимум 3 варианта заголовка:

- **Вариант 1 — поисковый**: максимально близок к целевому запросу. Пример: «Публикация в Федресурсе: кто обязан размещать сведения».
- **Вариант 2 — рекомендательный**: строится от проблемы пользователя. Пример: «Компания обязана публиковаться в Федресурсе. Как понять, касается ли это вас».
- **Вариант 3 — гибридный**: сочетает запрос и интерес. Пример: «Федресурс: какие сообщения обязана публиковать компания и что будет за пропуск».

При необходимости можно предложить до 5 вариантов. Article Writer выбирает основной вариант с учётом SEO-ТЗ.

## 7. Обложка

Первая картинка статьи имеет особое значение. Она должна:

- быть непосредственно связана с темой;
- легко считываться в маленькой карточке;
- не вводить пользователя в заблуждение;
- не быть визуальным кликбейтом;
- не содержать чрезмерное количество текста;
- выглядеть естественно, а не как перегруженный рекламный баннер.

SEO Analyst должен предложить концепцию обложки в формате:

- Что изображено: …
- Главный объект: …
- Эмоция / задача: …
- Что нельзя использовать: …
- Текст на изображении: не нужен / допустим короткий текст …

Article Writer не создаёт изображение, а только передаёт концепцию.

## 8. Первые 170 символов

Первые предложения статьи критически важны. Для платного продвижения первые 170 символов могут использоваться как текст рекламной карточки.

Первые 170 символов должны:

- сразу вводить в проблему;
- давать конкретную причину продолжить чтение;
- не содержать формальных вступлений;
- не начинаться с истории темы, если она не нужна;
- не повторять заголовок другими словами.

Нельзя начинать с: «В современном мире...», «На сегодняшний день...», «В данной статье рассмотрим...», «Сегодня поговорим о...».

## 9. Лид

Рекомендуемая длина лида: 1–3 коротких абзаца.

Задача: за первые 10–15 секунд подтвердить пользователю: «Я открыл именно тот материал, который мне нужен».

Хороший лид содержит: проблема + последствие / интерес + обещание конкретного ответа.

## 10. Удержание

После лида нельзя сразу переходить к длинному теоретическому объяснению. В первых 20–25% статьи пользователь должен получить минимум один существенный ответ. Не откладывать главную ценность статьи до конца.

> Плохая структура: длинное вступление → история вопроса → определения → законодательство → через 5000 знаков ответ.
>
> Хорошая структура: проблема → короткий ответ → объяснение → подробности → инструкция / пример.

## 11. Объём

У Дзена нет универсального SEO-требования «статья должна быть X символов». Объём определяется темой и интентом.

Для экспертных B2B-материалов Content Factory рекомендуется ориентир: 4 000–7 000 знаков без пробелов. Для сложного материала допустимо: 7 000–10 000 знаков.

Более длинный материал разрешён, только если дополнительный объём действительно добавляет ценность. Не увеличивать объём ради SEO.

## 12. Абзацы

Дзен в первую очередь читают с мобильных устройств:

- избегать длинных полотен;
- один абзац обычно 2–5 предложений;
- регулярно менять визуальный ритм;
- использовать подзаголовки;
- использовать списки там, где они упрощают понимание.

Не делать весь материал набором абзацев по одному предложению.

## 13. Подзаголовки

H2 должны одновременно помогать навигации, продолжать историю статьи, раскрывать дополнительные запросы и создавать причины продолжить чтение.

> Хорошо: «Кому действительно нужно подавать сообщение»; «Три рабочих дня: с какого момента считать срок»; «Что произойдёт, если ничего не публиковать».
>
> Слабее: «Общие сведения»; «Основные положения»; «Особенности»; «Важная информация».

## 14. SEO

SEO для Дзена обязательно сохраняется. Использовать:

- основной запрос;
- естественные словоформы;
- дополнительные запросы;
- вопросные запросы;
- тематическую лексику / LSI;
- связанные сущности.

Основной запрос или его естественная форма желательно использовать в заголовке, в первых абзацах, минимум в одном подзаголовке, если естественно, и в основном тексте.

Не использовать грамматически неправильные exact-match конструкции.

## 15. Особенность SEO для Дзена

SEO-запрос нельзя делать единственной логикой статьи.

> Запрос «федресурс сообщение» не означает, что нужно писать «Федресурс сообщение — это...». Использовать: «сообщение в Федресурсе», «публикация сообщения в Федресурсе», «размещение сведений в Федресурсе».

## 16. LSI и сущности

Использовать LSI для полноты темы, а не ради количества слов. SEO Analyst должен определить:

- организации;
- документы;
- процессы;
- профессиональные термины;
- связанные действия;
- причины;
- последствия;
- целевые группы пользователей.

Article Writer использует их естественно.

## 17. Экспертность

Материал должен содержать признаки реальной ценности. По возможности использовать:

- конкретные примеры;
- разбор ситуации;
- объяснение причин;
- пошаговые действия;
- собственные выводы;
- практические нюансы;
- комментарий специалиста;
- актуальные источники;
- реальные документы;
- кейсы;
- данные.

Не создавать видимость экспертности сложной терминологией.

## 18. Оригинальность

Материал должен быть самостоятельным. Нельзя механически копировать статью с сайта компании, Клерка, РБК, Sostav, другого канала Дзена или другой площадки.

Если Content Factory получает существующую статью с другой площадки, необходимо создать самостоятельную адаптацию под Дзен. Нужно менять угол подачи, заголовок, лид, композицию, структуру, подачу примеров и выводы. Не делать поверхностный рерайт слово в слово.

## 19. Самодостаточность статьи

Статья должна полностью отвечать на заявленный вопрос внутри Дзена. Нельзя использовать модель: «Начало инструкции здесь, продолжение читайте на нашем сайте». Внешняя ссылка может дополнять материал, но не заменять ответ.

## 20. Коммерческий контент

Коммерческая вставка допустима, если она логично продолжает проблему пользователя. Статья не должна выглядеть как рекламный лендинг с первого абзаца.

> Рекомендуемая модель: полезный контент → проблема → сложность самостоятельного решения → возможное решение через проект.

CTA должен быть мягким.

> Пример: «Если не хотите самостоятельно разбираться с формой сообщения, подготовку публикации можно поручить специалистам».

Не использовать агрессивные «Закажите прямо сейчас!», «Только сегодня!», если это не обусловлено реальным предложением.

## 21. Ссылки

Внешние ссылки допускаются только тогда, когда они нужны пользователю. Статья должна оставаться полноценной без перехода. Не перегружать материал ссылками.

Приоритет: полезность → внутренние материалы канала → источник информации → релевантная коммерческая ссылка, если она разрешена задачей.

Не вставлять ссылки исключительно ради SEO.

## 22. Внутренняя перелинковка

По возможности предлагать 1–3 связанных материала канала. SEO Analyst должен указывать рекомендуемые темы для перелинковки. Не придумывать URL.

## 23. Иллюстрации

Для экспертной статьи рекомендуется минимум: обложка + 1–3 дополнительных визуальных элемента при необходимости. Это могут быть: схема, таблица, скриншот, пример, чек-лист, инфографика, документ, тематическое изображение.

Иллюстрации должны помогать понимать материал. Не вставлять изображения только для увеличения длины публикации.

## 24. Таблицы

Использовать, если нужно сравнить варианты, показать сроки, классифицировать ситуации, сопоставить условия или сократить сложное объяснение. Таблица должна быть простой для мобильного чтения. Не делать широкие таблицы с большим количеством колонок.

## 25. Крючки удержания

Использовать естественные смысловые переходы.

> Примеры: «Но здесь есть важное исключение»; «Именно на этом этапе чаще всего возникает проблема»; «Для разных организаций правило работает по-разному»; «Разберём на простом примере»; «Есть ещё один риск, который часто упускают».

Не использовать искусственные: «Но самое интересное впереди!», «Вы будете шокированы следующим пунктом!».

## 26. Практика

Для экспертных статей желательно включать минимум один практический элемент: пример, алгоритм, чек-лист, таблицу, разбор ситуации или пошаговую инструкцию. Статья не должна состоять только из пересказа законодательства или теории.

## 27. FAQ

FAQ необязателен. Добавлять его только если есть дополнительные реальные вопросы пользователей. Не использовать FAQ как место для механического включения ключевых слов.

## 28. Концовка

Не писать формальный SEO-вывод «Таким образом...» или «Подводя итог...», если он просто повторяет статью.

Концовка должна делать одно из действий:

- давать короткий алгоритм;
- формулировать главный вывод;
- предлагать следующий шаг;
- задавать содержательный вопрос;
- приглашать изучить связанный материал;
- предлагать обратиться за помощью, если это предусмотрено проектом.

## 29. Вовлечение

Допустимо заканчивать статью вопросом, если он действительно вызывает профессиональное обсуждение.

> Пример: «Сталкивались ли вы с ситуацией, когда обязанность публикации обнаружилась уже после истечения срока?»

Не использовать пустое «А что думаете вы? Пишите в комментариях!» в каждой статье.

## 30. Требования Дзена

Запрещено использовать:

- кликбейт, обманывающий ожидания;
- искусственное завышение показателей;
- спам;
- неоригинальный контент;
- незаконный контент;
- шокирующий контент;
- другие категории контента, ограниченные правилами Дзена.

Карточка публикации должна соответствовать тем же требованиям, что и сама статья.

## 31. Платное продвижение

Если статья потенциально будет использоваться в VK Рекламе, обязательно проверить:

- заголовок — не более 70 символов;
- первая картинка — готова работать как рекламная обложка;
- первые 170 символов — понятны отдельно от остального текста и содержат причину открыть статью;
- статья — самодостаточна и соответствует правилам Дзена.

## 32. Что SEO Analyst должен добавить в SEO-ТЗ для Дзена

При площадке DZEN обязательны дополнительные поля:

- **DZEN ANGLE** — какой угол подачи используется;
- **READER PROBLEM** — какую конкретную проблему пользователя решаем;
- **PROMISE** — что пользователь получит после прочтения;
- **TITLE OPTIONS** — минимум три варианта заголовка: SEO, recommendation, hybrid;
- **CARD HOOK** — текст первых 170 символов;
- **COVER CONCEPT** — описание первой картинки;
- **RETENTION PLAN** — какие элементы удерживают внимание по ходу статьи;
- **PRACTICAL VALUE** — какой практический элемент получает пользователь;
- **ENGAGEMENT** — есть ли естественный повод оставить комментарий / сохранить / поделиться.

## 33. Что Article Writer должен проверить перед сохранением

DZEN QA:

- [ ] Title соответствует содержанию
- [ ] Title до 70 символов
- [ ] Основной запрос учтён
- [ ] Первые 170 символов работают как самостоятельный hook
- [ ] Главный ответ появляется в первых 25% статьи
- [ ] Нет длинного формального вступления
- [ ] Есть практическая ценность
- [ ] Есть признаки экспертности
- [ ] Структура удобна для мобильного чтения
- [ ] Нет кликбейта
- [ ] Материал самодостаточен
- [ ] Материал оригинален по подаче
- [ ] Нет SEO-переспама
- [ ] Обложка соответствует теме

Если любой критический пункт имеет NO, материал необходимо доработать перед финализацией.

## 34. Дополнение для SEO Analyst

При выборе площадки «Дзен» SEO Analyst должен дополнительно анализировать сам Дзен: какие статьи по теме уже публикуются, какие углы подачи используют авторы, какие заголовки повторяются и как сделать материал отличающимся от шаблонного пересказа.

Для Дзена SEO Analyst работает в режиме:

> Яндекс + Дзен + рекомендации + заголовки + обложка + удержание

## 35. Итог для SEO Analyst / Article Writer

- Площадка требует одновременно SEO-оптимизации и работы с рекомендательной лентой (заголовок, обложка, первые 170 символов, удержание).
- SEO-ТЗ для Дзена должно включать дополнительные поля из раздела 32 (DZEN ANGLE, READER PROBLEM, PROMISE, TITLE OPTIONS, CARD HOOK, COVER CONCEPT, RETENTION PLAN, PRACTICAL VALUE, ENGAGEMENT).
- Перед сохранением статьи — проверка по чек-листу DZEN QA (раздел 33).
- Объём — ориентир 4 000–7 000 знаков без пробелов (до 10 000 для сложного материала), без искусственного наращивания.
- Коммерческий блок — мягкий CTA, вставка только после полезного контента, без лендингового тона с первого абзаца.
