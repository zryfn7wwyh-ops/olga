## 3. Детальные находки

### 3.1 Сильные стороны (уже работает)

- **Свежесть**: `dateModified` у 10 из 11 проверенных страниц — июнь 2026, сильный сигнал для AI-цитирования
- **FAQPage уже размечен через Microdata** на 9 из 10 страниц (не JSON-LD, но валидно) — самодостаточные ответы со ссылками на конкретные статьи закона и суммы штрафов
- **Готовая таблица дифференциации от конкурентов** (без указания имён) — готовый материал для comparison-контента, самый цитируемый AI формат (~33% по исследованиям)
- **Именной эксперт найден**: Дарья Кокорикова — основатель сервиса, финансовый директор ООО «Кейс Групп», эксперт с 10-летним опытом, с прессой в 3 изданиях
- **Лид-магниты** («Бесплатный аудит», «Тест на знание 152 ФЗ») — потенциал для дополнительного контента
- **Реальные цифры**: 2500 регистраций, 65 000 клиентов, 47 000 посетителей вебинаров, 3000 на годовом сопровождении

### 3.2 Главная страница — отдельно

Главная (`https://roskom.online/`) подтверждена через `@id` в schema и canonical.

- Title и H1 посвящены одной услуге («Разработка документов по персональным данным»/«Подготовка документов для работы с персональными данными»), а не бренду или всему спектру — название компании стоит в конце длинного title. Это слабое место для брендовых запросов и topical authority: AI-движки должны воспринимать главную как хаб всей темы, а не лендинг одной услуги.
- FAQ на главной (7 пар) — самое общее/фундаментальное: «Что относится к персональным данным», «Что понимается под обработкой ПДн» — хорошо закрывает definition-блоки, которых не хватало на узких страницах услуг.
- **Прямое противоречие**: «Штраф до 18 млн. руб.» (главная) vs «15 000 000 ₽» (pdpolicy).
- «СМИ о нас» на главной — только 2 из 3 известных ссылок (нет РБК).
- «Наши ключевые услуги» — ссылки на 7 из ~12 реальных страниц услуг.
- Блоки метрик и таблица дифференциации — идентичны версии с других страниц (переиспользуемые компоненты — правка в одном месте обновит всюду).

## 4. Приложения — готовый код

### Приложение A. Person schema (Дарья Кокорикова)

```html
<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "Person",
  "@id": "https://roskom.online/#daria-kokorikova",
  "name": "Дарья Кокорикова",
  "jobTitle": "Основатель сервиса «Роском Онлайн», финансовый директор ООО «Кейс Групп»",
  "description": "Эксперт по корпоративной защите персональных данных с 10-летним опытом",
  "worksFor": {
    "@type": "Organization",
    "name": "Роском Онлайн",
    "url": "https://roskom.online/"
  }
}
</script>
```

*`sameAs` не заполняем — личных профилей (LinkedIn/VK/сайт) у Дарьи нет, подтверждено.*

### Приложение D. robots.txt — директивы для AI-ботов

Добавить в конец файла (ничего существующего не удалять):

```
User-agent: GPTBot
Allow: /

User-agent: ChatGPT-User
Allow: /

User-agent: ClaudeBot
Allow: /

User-agent: anthropic-ai
Allow: /

User-agent: PerplexityBot
Allow: /

User-agent: Google-Extended
Allow: /

User-agent: YandexBot
Allow: /
```

**Как вставить без разработчика** (сайт на WordPress + Yoast SEO): админка → **SEO** → **Инструменты** → **Редактор файлов** → вставить блок в конец → сохранить. Если файла нет — Yoast предложит его создать.

**Проверка результата**: Google Search Console → «Инструмент проверки robots.txt» (для `Google-Extended`); Яндекс.Вебмастер → «Анализ robots.txt» (для `YandexBot`). Проще всего — прислать содержимое файла после правки текстом, проверю построчно.
