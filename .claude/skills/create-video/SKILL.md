# Производство ролика «Роском Онлайн»

**Главный принцип:** сначала качественный сценарий, затем утверждение пользователя, только после этого озвучка, анимация и монтаж.

Рабочая директория — `roskom-video-studio/`, все команды выполняются из неё. Правила проекта — `roskom-video-studio/CLAUDE.md`.

## Где остановилась работа
В начале работы с существующим проектом выполни `npm run status -- <проект>`.

| Статус | Что делать |
|---|---|
| DRAFT | писать сценарий (этап 1) |
| AWAITING_APPROVAL | ждать ответа пользователя. Если в этом разговоре текст ещё не показан — показать его снова (`npm run script-show`). Ничего не производить |
| APPROVED | можно производить (этап 2) |
| PRODUCTION | производство прервано — перезапустить build |
| COMPLETED | готово |
| FAILED | см. history в project.json и quality-report.json |

После перезапуска никогда не начинай производство без статуса APPROVED.

## ЭТАП 1. Сценарий и согласование

**Запрещено до утверждения:**
- генерация озвучки, вызовы SpeechKit, ElevenLabs и других TTS;
- раскадровка для производства;
- анимация, монтаж, рендер, экспорт MP4;
- команды `build`, `still`, `storyboard-init`, `voices`.

Разрешено: исследование, текст, проверки, расчёт длительности, черновики.

1. `npm run new -- "<тема>" --type <explainer|three-mistakes|myth-truth|qa|news> [--duration short|medium|long]` → статус DRAFT. Тип выбери по смыслу темы (`npm run types`).
2. Агент **researcher**: факты с официальными источниками → `research.md`.
3. Агент **scriptwriter**: аудитория, проблема, 3 хука с оценками, полный текст, редакторская проверка → `scripts/draft.json`.
4. Агент **legal-reviewer**: проверка всех юридических утверждений.
   - Неподтверждённое — убрать из текста.
   - Спорное — внести в `legalWarnings`, чтобы пользователь увидел до утверждения.
5. `npm run script-check -- <проект>` — исправлять, пока нет ✗.
6. `npm run script-submit -- <проект>` → новая версия `scripts/script_vN.md`, статус AWAITING_APPROVAL. Команда печатает готовый текст для чата.
7. **Покажи пользователю вывод script-submit ЦЕЛИКОМ, дословно** — от «Тема видео» до «Статус». Затем задай вопрос: «Утверждаем сценарий или внесём правки?». **Остановись.**

### Правила показа сценария (строго)
- Пользователь видит 100% текста, который пойдёт в озвучку, слово в слово.
- Запрещено:
  - показывать только начало, хук или тезисы;
  - ставить многоточия вместо частей текста;
  - пересказывать сценарий;
  - отправлять только ссылку на файл;
  - сокращать длинный текст.
- Если сообщение получается слишком длинным — выведи сценарий несколькими сообщениями подряд, затем задай вопрос об утверждении.
- Перед сценарием можно 1–2 строками сказать, что сделано. После вопроса ничего не делать.

### Правки сценария
Если пользователь просит изменить текст, правь **сценарий, а не видео**:
1. Обнови `draft.json` через scriptwriter, заполни `changeNote`.
2. Выполни script-check и script-submit — это новая версия vN+1.
3. Снова покажи **весь** обновлённый сценарий, а не только изменённый фрагмент, и снова спроси об утверждении.

Как трактовать просьбы:
- «Сделай хук сильнее» — три новых хука, выбор лучшего.
- «Более продающим» — сильнее переход к услуге, пользу сохранить.
- «Сократи до N секунд» — сохранить хук, главную мысль и CTA.
- «Больше конкретики» — факты, пример, действия.
- «Убери рекламу в конце» — CTA заменить полезным выводом.

## Утверждение
Утверждение — только явная команда пользователя: «Утверждаю», «Согласовано», «Запускай производство», «Делай видео по этому тексту» или другая однозначная.

**Не утверждение:**
- «спасибо», «посмотрю», «интересно»;
- молчание;
- нейтральный комментарий;
- вопрос.

Если сомневаешься — переспроси.

Перед утверждением проверь, что пользователь утверждает **последнюю показанную версию**. Затем:
```bash
npm run approve-script -- <проект> --version <N> --message "<дословно слова пользователя>"
```
Команда сама откажет, если версия не последняя или сообщение не является утверждением. Утверждённый текст после этого не меняется. Новая правка — новая версия и новое утверждение.

## ЭТАП 2. Производство (только при статусе APPROVED)
1. `npm run storyboard-init -- <проект>` — каркас раскадровки из утверждённого текста.
2. Агент **storyboard-director** и затем **video-director** заполняют визуал. **Тексты фраз (voice) не трогать.**
   - Разрешено: менять разбивку фраз по сценам и добавлять технические записи `say` (произношение, ударение `**слово**`) без изменения слов.
3. `npm run validate -- <проект>`.
4. `npm run build -- <проект>` — долгая команда, запускай в фоне.
   - Сборка сама откажет, если текст раскадровки отличается от утверждённого.
   - Сборка ставит статус PRODUCTION, а по итогу COMPLETED или FAILED.
5. Агент **quality-reviewer**: quality-report.json, контрольные кадры (`npm run still`), первые 3 секунды.
   - Технические проблемы исправляй в монтаже (`--scenes N`). **Никогда не переписывай утверждённый текст ради исправления видео.**
6. Пользователю:
   - final.mp4 и cover.png (через SendUserFile);
   - длительность и голос;
   - что в publication.md.
   Публиковать без отдельного разрешения нельзя.

### Первые 3 секунды
- Сразу визуал, связанный с хуком, — без заставки, статичного логотипа и пустого фона.
- Маскот в движении, ключевые слова хука выделены (`highlight`).
- Примеры:
  - «форма заявки» → `browser` с `highlightField` (поле «Телефон»);
  - «три ошибки» → `cards` с тремя предупреждениями;
  - «зарегистрировались в РКН?» → `registry` со значком проверки и предупреждением.
- Субтитры не закрывают важное.

## Пакет роликов («подготовь 5 роликов про …»)
1. Агент **content-planner** — 5 тем.
2. По каждой — этап 1 (свой проект, 3 хука, полный сценарий).
3. Показать **каждый** сценарий целиком. Если сценарии длинные — по одному или двум в сообщении.
4. Утверждения собирать по каждому ролику отдельно.
5. Производить только утверждённые. Остальные остаются в AWAITING_APPROVAL.
6. Пакетное производство автоматически не запускать.
