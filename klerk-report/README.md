# Отчёт по контенту klerk.ru

Инструмент сравнивает нашу статью на klerk.ru со статьёй конкурента по одному
ключевому запросу: считывает текущее число просмотров и «читают сейчас»,
запоминает снимок на дату и при следующем запуске показывает, у кого прирост
просмотров за период больше — та статья и «выигрывает» в этом сравнении.

## Установка

```bash
cd klerk-report
python3 -m venv .venv && source .venv/bin/activate   # опционально
pip install -r requirements.txt
```

Если счётчики на странице подгружаются через JavaScript и обычный запрос их
не видит (см. раздел «Если просмотры не находятся» ниже), дополнительно:

```bash
pip install playwright
playwright install chromium
```

## Настройка

```bash
cp config.example.yaml config.yaml
```

В `config.yaml` для каждого ключевого запроса укажите:

```yaml
items:
  - query: "регистрация ООО в 2026 году"
    our_url: "https://www.klerk.ru/blogs/roskom24/659984/"
    competitors:
      - label: "Конкурент 1"
        url: "https://www.klerk.ru/blogs/.../..."
```

Можно указывать несколько конкурентов на один запрос и несколько запросов.

## Использование

1. Сегодня снимаем первый срез:

   ```bash
   python -m klerk_report update
   ```

2. Через несколько дней (например, через неделю) снимаем второй срез:

   ```bash
   python -m klerk_report update
   ```

3. Смотрим отчёт — сравнение идёт между двумя последними снимками:

   ```bash
   python -m klerk_report report
   # или сохранить в файл:
   python -m klerk_report report --out reports/2026-08-24.md
   # или в CSV:
   python -m klerk_report report --format csv --out reports/2026-08-24.csv
   ```

Отчёт покажет по каждому запросу: нашу статью и статью(и) конкурента(ов) со
ссылками, текущие просмотры, прирост просмотров за период между снимками,
текущее «читают сейчас» и кто выигрывает по приросту просмотров.

`update` можно запускать по расписанию (cron / планировщик задач), тогда
`report` всегда будет сравнивать последние два снимка.

## Если просмотры не находятся ("н/д" в отчёте)

Парсер использует эвристики (типовые CSS-классы вроде `.article-views`,
`[class*="views"]`, а также текстовые паттерны рядом со словом «просмотр»),
потому что точная вёрстка страниц klerk.ru не была доступна для проверки при
написании инструмента (сеть до klerk.ru была заблокирована в среде
разработки). Если эвристика не сработала на реальной странице:

```bash
python -m klerk_report inspect https://www.klerk.ru/blogs/roskom24/659984/
```

Команда покажет заголовок, что нашла эвристика, и текстовый контекст вокруг
слов «просмотр» / «читают» / «онлайн» — это поможет понять, где на странице
лежат нужные цифры. Дальше откройте страницу в браузере, через «Инспектировать
элемент» найдите точный CSS-класс блока с просмотрами/читателями и впишите
его в `config.yaml`:

```yaml
items:
  - query: "..."
    our_url: "..."
    views_selector: ".найденный-класс"       # переопределяет эвристику
    reading_selector: ".другой-класс"
    competitors:
      - label: "Конкурент 1"
        url: "..."
        views_selector: "..."                # можно свой на каждую статью
```

Если после этого числа всё равно не находятся — вероятно, счётчик
подгружается через JavaScript уже после загрузки страницы. В этом случае
включите в `config.yaml` (глобально или для конкретной статьи):

```yaml
settings:
  render: true
```

и установите playwright (см. «Установка»).

## Структура данных

История снимков хранится в `data/history.json` — по одному снимку на URL на
дату (при повторном `update` в тот же день снимок за эту дату
перезаписывается, а не дублируется). Файл можно коммитить в git, чтобы не
терять историю между запусками с разных машин.
